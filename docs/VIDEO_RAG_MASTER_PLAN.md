## 1. 项目目标

在现有产品手册图文 RAG 系统上增加两类能力：

1. 用户通过文字问题检索视频知识库，返回相关教学视频的准确时间段；
2. 用户上传自己的操作或故障视频，系统识别当前步骤和操作偏差，并检索对应的手册章节、手册图片和标准视频片段。

最终输出至少包含：

- 基于证据的文字答案；
- 对应手册章节与手册图片；
- 一个或多个带 `start_time` / `end_time` 的视频片段引用；
- 对用户视频的步骤位置、偏差类型、下一步建议和置信度；
- 高风险或低置信度场景下的安全降级提示。

产品可部署优先，论文贡献从真实系统研发过程中提炼，不以训练超大模型为目标。

## 2. 已确认约束

- 视频知识库检索和用户上传视频诊断都要支持；
- 当前没有现成视频资料；
- 采用“开放许可视频开发 + 独立创作者委托录制测试”的数据路线；
- 第一阶段接受只覆盖 8–12 类代表性产品；
- 采用 AI 预标注，由 1 名复核人完成人工最终判断；
- 可公开脱敏后的代码和标注；
- 可使用两张 RTX 4090 24GB 和其他必要资源；
- 目标为 2–3 个月形成首次 SCI 投稿；
- 产品可用性优先于期刊等级。

## 3. 当前系统基线

现有系统处理流程：

```text
POST /chat
  -> 客服/技术分类
  -> 产品路由
  -> BM25 + Dense 召回
  -> 候选融合与 rerank
  -> 返回完整 parent section
  -> 注入正文、图片锚点和 caption
  -> LLM 生成
  -> 文字 + <PIC> 图片输出
```

基线数据规模：

- 产品手册：39 份；
- 章节：1,943 个；
- 检索块：6,570 个；
- 手册图片：2,605 张；
- 图片 caption：2,567 条；
- 公开问题：400 条，其中技术题 350 条。

需要优先修复的基线问题：

- 立即轮换源码中出现过的上游密钥，并移出 `config_runtime.py`；
- 当前公开题集被用于规则调优，不能作为论文独立测试集；
- 当前多模态验证主要是格式和资源存在性验证，不是真实理解准确率；
- 用户图片进入生成模型，但没有参与图像到知识库的检索；
- 缺少正式单元测试、检索回归测试、并发测试和隐私测试；
- session 无过期机制，超时不能真正停止后台线程；
- 部分图片 caption 存在乱码；
- `.DS_Store`、脚本权限和文档漂移导致交付检查不稳定。

## 4. 第一阶段产品范围

计划先覆盖以下 8 类产品：

1. Air Fryer；
2. Espresso Machine；
3. Pressure Cooker；
4. Washing Machine；
5. Vacuum；
6. Printer；
7. Camera；
8. 电钻。

选择依据：

- 已在现有手册库中；
- 操作步骤和部件状态明显；
- 公开视频相对容易获取；
- 可以覆盖烹饪、家电、清洁、办公、影像和电动工具；
- 同时包含普通操作、维护、故障和安全类场景。

若第一周版权或实物可得性审计不通过，可缩减到 5–6 类，但不得随意更换测试集产品。

## 5. 目标架构

### 5.1 离线视频知识库构建

```text
视频采集与许可登记
  -> FFmpeg 元数据与镜头检测
  -> 重叠时间窗口/语义片段切分
  -> ASR 语音转写与词级时间戳
  -> OCR 提取型号、按钮和错误码
  -> 关键帧抽取
  -> 视频片段视觉向量
  -> VLM 生成结构化步骤描述
  -> 手册章节/图片/步骤/视频时间段对齐
  -> 文本索引 + 视频索引 + 时序步骤图
```

### 5.2 文字查询

```text
用户问题
  -> 产品与任务类型识别
  -> 手册、图片、ASR/OCR、视频片段联合召回
  -> 查询自适应的模态融合
  -> 跨模态 rerank
  -> 证据约束生成
  -> 文字 + 手册图 + 视频时间段
```

### 5.3 用户视频诊断

```text
用户视频
  -> 异步解析
  -> 产品、部件、动作和状态识别
  -> 检索标准操作流程
  -> 用户片段与标准步骤序列对齐
  -> 判断当前步骤、遗漏、顺序错误、方向错误或危险动作
  -> 返回下一步和对应三模态证据
```

## 6. 方法设计

### 6.1 多层索引

索引至少分为三层：

- 产品层：产品、型号、别名和外观特征；
- 过程层：安装、清洁、维护、排障等 procedure；
- 证据层：手册段落、图片、ASR/OCR 文本、视频片段和关键帧。

### 6.2 视频片段表示

每个片段保存：

- `video_id`、起止时间和来源许可；
- ASR 文本与 OCR 文本；
- 关键帧路径；
- 产品、部件、动作和状态；
- 视频向量、文本向量；
- 标准步骤 ID；
- 对应手册章节和手册图片；
- 是否属于危险操作。

### 6.3 检索与融合

MVP 使用可解释的分阶段方案：

1. 产品过滤；
2. BM25 和文本 Dense 召回；
3. 视频视觉向量召回；
4. RRF 或归一化加权融合；
5. 文本 reranker 和 VLM 视觉复核；
6. 按视频时间重叠和步骤 ID 去重。

论文版比较固定权重与查询自适应权重。查询自适应特征包括问题类型、是否包含错误码、是否描述视觉状态、是否询问操作顺序，以及是否上传视频。

### 6.4 步骤与偏差诊断

初版使用动态规划、DTW 或 Viterbi 将用户动作片段对齐到标准步骤图。综合分数包括：

- 视觉动作相似度；
- 部件和对象相似度；
- ASR/OCR 相似度；
- 步骤顺序约束；
- 前后状态一致性；
- 安全关键步骤权重。

偏差类别固定为：

- `correct`；
- `missing_step`；
- `wrong_order`；
- `wrong_part`；
- `wrong_orientation`；
- `unsafe_action`；
- `unknown`。

## 7. 数据计划

### 7.1 目标规模

- 公开视频：160–240 条；
- 视频总时长：25–40 小时；
- 标准步骤时间段：1,200–2,000 个；
- 文字检索问题：1,000–1,500 条；
- 独立创作者委托/合作录制视频：40–80 条；
- 每条测试问题均具备手册章节、图片和视频时间段证据。

### 7.2 数据来源

- 具有研究许可的公开视频数据集；
- 厂商公开教学视频；
- 只发布公开视频 ID、URL、时间戳和自有标注，不重新分发无授权视频；
- 委托或合作录制视频签署明确许可，作为稳定的独立/OOD 测试集；
- COIN、CrossTask、HowTo100M 等只作为外部训练或泛化参考，不替代领域测试集。

### 7.3 标注模式

每条标注至少包含：

```text
video_id, product_id, procedure_id, step_id,
start_time, end_time, step_description,
objects_and_parts, action, state_before, state_after,
manual_section_id, manual_image_ids,
error_type, severity, evidence_text
```

标注与复核原则：

- AI 对全部候选视频生成结构化预标注，并保留模型、提示词版本和原始输出；
- R1 全量复核所有 AI 保留视频，可修正类别、过程相关性、功能步骤、时间边界、隐私和安全标签；
- R1 对 AI 拒绝视频进行固定种子、按产品类别分层的 20% 抽查；
- R1 全量复核冻结后的 100 个检索问题及其相关性、时间边界和来源泄漏标签；
- 数据划分在模型选择前按来源冻结，测试集不得用于提示词或阈值调优；
- 报告 AI 接受项修正率、最终接受率、拒绝抽查误拒率及 Wilson 95% 置信区间；
- 由于只有一名人工复核人，不计算或声称 Cohen's Kappa、Krippendorff's Alpha 等标注员间一致性。

### 7.4 防止数据泄漏

- 按原始视频、频道/来源、录制者和设备实例划分；
- 不允许将同一视频的相邻片段随机分到训练集和测试集；
- 委托录制视频只进入 OOD 测试集；
- 所有规则和阈值在测试集冻结前确定；
- 测试集答案和时间边界不进入 prompt 调优。

## 8. 工程设计

建议新增独立 `video_rag/` 包，避免继续扩张现有 `agent.py`：

```text
video_rag/
  schemas.py
  ingest.py
  segmenter.py
  asr.py
  ocr.py
  visual_encoder.py
  captioner.py
  aligner.py
  video_index.py
  multimodal_retriever.py
  procedure_graph.py
  deviation_detector.py
  safety_policy.py
  jobs.py
```

接口规划：

```text
POST /v2/video-jobs
GET  /v2/video-jobs/{job_id}
POST /v2/chat
GET  /v2/videos/{video_id}
```

视频处理采用异步任务；知识库视频通过原视频加时间参数或 HLS 播放，不在每次请求时重新裁剪。

## 9. 模型与资源

候选组件：

- 视频/VLM：Qwen3-VL 8B 或经第一周显存、速度和定位准确率实测后的同级模型；
- 视频表征：InternVideo2/2.5 中小型版本；
- ASR：Whisper large-v3 系列；
- OCR：PaddleOCR；
- 文本向量：现有 BGE-M3；
- 文本 rerank：现有 BGE reranker；
- 元数据：开发期 SQLite，部署期 PostgreSQL；
- 对象存储：本地目录或 MinIO；
- 向量索引：MVP 使用 FAISS，规模扩大后再评估 Qdrant/Milvus。

GPU 建议：

- GPU 0：视频/VLM 理解和用户视频诊断；
- GPU 1：文本生成、视频向量或 rerank；
- 离线构建阶段两卡并行处理 ASR、caption 和 embedding；
- 论文主体使用开源模型，商业 API 仅作为性能上限参考。

## 11. 实验计划

### 11.1 基线

1. 当前文本+图片 RAG；
2. 仅 ASR 文本的视频 RAG；
3. 仅视频视觉向量；
4. 文本与视频候选简单拼接；
5. BM25 + Dense + RRF；
6. 可复现的 VideoRAG 风格方法；
7. 本项目的层次化三模态检索与步骤对齐。

### 11.2 指标

视频检索：

- Recall@1/5/10；
- mAP；
- nDCG@10。

时间定位：

- R@1, IoU=0.3/0.5/0.7；
- mean IoU。

步骤与诊断：

- Step Accuracy；
- Next-step Accuracy；
- Macro-F1；
- Unsafe-action Recall。

答案质量：

- 人工正确性；
- 证据忠实度；
- 手册—视频一致性；
- 引用时间段有效率；
- LLM Judge 只作为辅助指标。

系统指标：

- P50/P95 延迟；
- GPU 显存；
- 索引构建速度；
- 单视频处理时间；
- 吞吐量和平均成本。

关键结果报告 bootstrap 95% 置信区间，并执行适当的配对显著性检验。

### 11.3 消融

- 去掉视觉特征；
- 去掉 ASR；
- 去掉 OCR；
- 去掉手册—视频对齐；
- 去掉时序顺序约束；
- 固定模态权重与动态权重；
- Chunk 与 Parent Section；
- 不同视频窗口长度；
- 不同 Top-K；
- 有无用户视频诊断。

## 14. 验收门槛

产品候选目标：

- 视频 Recall@5 不低于 80%；
- R@1, IoU=0.5 不低于 50%；
- 步骤/偏差诊断 Macro-F1 不低于 70%；
- 手册图片和视频时间引用有效率达到 100%；
- 知识库检索 P95 不超过 5 秒；
- 完整回答 P95 尽量不超过 15 秒；
- 60 秒内用户视频的异步分析尽量控制在 30–60 秒；
- 高风险或低置信度请求必须触发安全降级。

论文 Go/No-Go：

- 提出方法需在至少两个核心指标上稳定优于最强可复现基线；
- 测试集必须独立且无来源泄漏；
- 至少完成一次外部数据集或跨产品泛化验证；
- 若方法增益不足，论文主张调整为“领域数据集 + 可解释系统 + 完整实证”，不得夸大算法创新。
