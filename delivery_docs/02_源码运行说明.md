# 源码与运行说明

## 1. 代码包说明

本代码包为 KBrag V6 初赛提交版，包含多模态客服智能体的核心源码、RAG 知识库、检索索引、图片 caption、启动脚本、验证脚本和交付文档。

评审可在隔离环境中完成：

1. 安装依赖；
2. 启动 `/chat` RESTful API；
3. 使用 smoke 脚本进行接口验证；
4. 阅读源码与文档复核核心模块。

## 3. 核心模块

| 文件 | 作用 |
| --- | --- |
| `api_server.py` | FastAPI 服务入口，提供 `GET /health` 和 `POST /chat`；在线场景在这里完成 service / tech 分类，并映射为 `fake_qid=0/64` |
| `agent.py` | 智能体主流程，根据 `question_id` 选择客服或技术 prompt；技术题执行产品路由、预检索、`search_manual` 工具调用和答案收束 |
| `llm_router.py` | 大模型调用路由，支持 OpenAI-compatible 接口 |
| `retrieval_engine.py` | 混合检索后端，实现 BM25、dense、RRF、rerank 和 parent section 返回 |
| `product_router.py` | 产品路由模块，识别问题涉及的产品、型号或候选手册 |
| `rerank_client.py` | rerank 服务客户端 |
| `submission_utils.py` | `[[PIC:...]]` 抽取、`<PIC>` 归一、图片数组生成、客服题清洗和最终格式化 |
| `parse_manuals.py` | 从 Markdown 手册生成结构化 section 和 retrieval chunks |
| `build_retrieval_index.py` | 根据 retrieval chunks 构建 BM25 与 FAISS 索引 |
| `generate_submission_v5.py` | 离线跑批脚本，文件名沿用历史命名，当前内容为 V6 主线 |
| `validate_delivery.py` | 交付包静态自检脚本 |
| `validate_performance.py` | 验证报告数据表生成脚本，产出产品路由、图文、入口路由、对话等验证表格 |

## 6. 默认配置与覆盖方式

默认配置集中在：

```text
config_runtime.py
```

包括：

- `/chat` Bearer Token；
- DeepSeek V4 Flash service / tech 二分类路由器；
- OpenAI-compatible 主回答模型；
- 远程 embedding 与 rerank 服务；
- 超时、并发、图片数量和图片大小限制；
- `RETURN_PARENT_SECTION=1` parent section 返回策略。

`api_server.py` 和 `llm_router.py` 启动时会调用 `apply_default_env()`，只为未设置的环境变量写入默认值。因此评审可直接启动，也可通过环境变量覆盖。

示例：

```bash
SILICONFLOW_BASE_URL="https://your-openai-compatible-endpoint/v1" \
SILICONFLOW_API_KEY="sk-..." \
SILICONFLOW_MODEL="your-model" \
./run_api.sh
```

私有部署可参考 `.env.example`。

```bash

```

- 必需源码、索引、手册、插图和交付文档是否存在；
- `run_api.sh`、`smoke_test.sh` 是否具备可执行权限；
- Python 源码是否可语法编译；
- 函数/类 docstring 注释覆盖率是否不低于 30%；
- 是否混入 `__pycache__`、`.bak`、运行期 trace/raw 等临时文件；
- 是否存在散落在非配置文件中的疑似密钥。

## 13. 代码注释与结构规范

本代码包采用模块化结构组织核心能力：

- API 层负责请求校验、鉴权、超时、trace、session 短历史和在线 service / tech 分类；
- Agent 层根据 `question_id` 选择客服或技术 prompt，并负责技术题检索工具、技术 prompt 和答案收束；
- 检索层负责 BM25、dense、RRF、rerank 和 parent section 返回；
- Formatter 层负责图片锚点抽取、`<PIC>` 归一和平台格式清洗。

注释覆盖率采用“有 docstring 的函数/类占全部函数/类的比例”作为自检口径。该口径比简单统计 `#` 行数更适合本工程，因为核心说明集中在模块、函数、类 docstring 和关键代码块注释中。当前自检结果为 47.3%，满足初赛“不低于 30%”的要求。

为保证交付包简洁，提交目录不包含：

- `.git/`
- 历史实验目录；
- 全量开发过程 trace/raw；
- Python 缓存；
- macOS 缓存；
- 旧版本手册归档；
- 大量临时 smoke 输出。

这些内容属于研发过程文件，不影响当前初赛版启动和验证。
