# 初赛提交材料总览

## 1. 提交对象

本目录为 DataFountain 竞赛「具有多模态能力的客服智能体设计」初赛提交代码包：

```text
V6_submit_code/
```

提交目标是让评审能够在隔离环境中完成三类动作：

1. 启动标准 RESTful API 服务；
2. 调用核心端点 `POST /chat` 验证文本与 Base64 图片请求；
3. 查阅源码、技术方案和验证报告，复核系统是否具备多模态客服智能体的核心能力。

## 5. 快速验证路径

评审或复核人员可按以下顺序验证：

```bash
cd V6_submit_code
pip install -r requirements.txt
./run_api.sh
```

另开终端执行：

```bash
./smoke_test.sh
```

提交前静态自检：

```bash
python validate_delivery.py
```

生成或刷新验证报告数据表：

```bash
python validate_performance.py
python validate_performance.py --api-base-url http://127.0.0.1:8000
```

## 6. 初赛版本能力边界

为避免交付材料夸大实现，本版本能力边界明确如下：

1. `/chat` 是唯一核心对话端点；`/health` 仅用于健康检查。
2. `images` 字段支持 Base64 data URL 校验，并可作为本轮多模态消息传入模型；当前稳定得分能力主要来自手册文本、手册插图、图片 caption 和图文锚点链路。
3. `session_id` 支持内存态短历史拼接，便于连续追问；提交版未接入数据库或 Redis 持久化记忆。
4. `stream` 字段作为协议兼容项保留，当前仍同步返回完整 JSON。
5. 提交版不在评审请求过程中自动改写手册或在线学习，避免线上知识库被污染；系统演进依赖离线验证、问题复盘、数据清理和索引重建。
6. 当前 API 默认只暴露 `search_manual` 主动检索工具，不重新启用旧版 `manual_reader/use_skill/list/read` 工具链。

## 7. 建议提交方式

建议将 `V6_submit_code/` 作为源码包整体提交，并随包提供 `delivery_docs/` 下的 Markdown 源稿。若平台要求 PDF，可将以下两份转换为 PDF：

```text
delivery_docs/03_技术方案说明.md
delivery_docs/04_验证报告.md
```

若需要单独上传接口说明或运行说明，可使用：

```text
delivery_docs/01_API接口说明.md
delivery_docs/02_源码运行说明.md
```
